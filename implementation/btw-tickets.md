## Read before any ticket

- **Gates for every ticket.** `npm run typecheck`, `npm run lint` and `npm test` pass at the end of the ticket. Never run `next dev` while `sam-ui.service` is up. Never run `./deploy.sh`, push or merge — that needs Colin's go.
- **The CLI's stream-json contract, proven 2026-10-03 (`/tmp/btw-probe.py`).** For a Claude-tier turn, the real command is `claude -p --input-format stream-json --output-format stream-json --verbose --model <m> [--session-id <id> | --resume <id>]` — note `-p` is a **bare flag** here, not `-p <prompt>`: with `--input-format stream-json` present, the CLI reads the prompt from stdin instead of argv. The first stdin line is `{"type":"user","message":{"role":"user","content":[{"type":"text","text":"<prompt>"}]}}\n`. A line written to stdin mid-turn reaches the model at its next step; closing stdin mid-turn does not kill the turn; a line arriving after the turn's last step gets answered as a second `result` from the same process. Today's code (`startTurn.ts`) instead passes `-p <prompt>` on argv and spawns with stdin `'ignore'` (`manager.ts`, `createArgs`) — that stays true for every tier except Max and Max 2.
- **Ticket order and why.** T1–T3 are test infrastructure and pure logic — no user-visible change, nothing to regress. T4 changes how a Max/Max2 turn is spawned but does not yet let anything use the new channel, so the app is unchanged from Colin's side. T5 is the feature's server half (a chat can take a side message). T6 is the client half (the send box actually offers it). T7 and T8 make a sent side message visible, live and after a reload. T9 is Colin's own verification, last.
- **The real CLI's `result` line is not type-first (SAM, live test 2026-10-03).** It prints `{"duration_api_ms":…,…,"type":"result",…}`; every other event starts `{"type":…`. Never detect a result by text prefix: parse the line and check the top-level `type`. The fake CLI's stream-json mode now prints results in the real key order so tests catch this.
- **Tier gating, everywhere.** Only `tier === 'max' || tier === 'max2'` ever takes this path. Fast, Pro and Gemini keep every byte of their current spawn and UI behaviour — grep for the tier check in each ticket's "Do not touch" before assuming a shared code path is safe to change.
- **Scope: text only.** A side message never carries attachments (the spec doesn't ask for it, and the probe only proves text). If files are staged when Colin tries to send into a running turn, the send is still blocked — don't build attachment support into this channel.
- **No existing automated browser/RTL harness.** `npm test` is `tsc -p tsconfig.test.json` then `node --test` over the emitted `.test-build/**/*.test.js` — there is no jsdom or testing-library in this repo. Anything that must be proven about `src/app/(app)/chat/page.tsx`'s own behaviour (must-do 1, 13) has to be extracted into a plain, dependency-free `.ts` module first (precedent: `src/lib/chatTier.ts` / `chatTier.test.ts`), exactly the way T6 does it. Don't try to add a browser test runner to satisfy this — checks 4, 5's browser half, 8 and 14 are Colin's own manual verification, covered by T9 only.
